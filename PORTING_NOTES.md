# Colosseum Duel — перенос на Unity: что уже сделано и что нужно доделать

> ⚠️ **Этот файл описывает исходное состояние архива и частично устарел.**
> Разделы 1, 2 и 5 (ручная сборка сцены, порядок работ) уже выполнены и заменены
> Editor-скриптом `Tools → Colosseum → Bootstrap project`. Актуальное состояние,
> список найденных багов и оставшиеся шаги — в **`IMPLEMENTATION_PLAN.md`**.
> Разделы 3 и 4 (git, GitHub Pages) всё ещё актуальны.

Этот архив — не готовая игра, а стартовая точка: **вся игровая логика** (стейт-машина
матча, физика движения/столкновений, урон, способности, предметы, опасные зоны арены,
ИИ бота) уже переписана на чистый C# и лежит в `Assets/Scripts/Core/`. Она специально
не зависит от `GameObject`/сцены — её можно тестировать даже без открытой сцены. А вот
**визуальная часть** (3D-модели, UI, ввод, сама сцена арены) в Unity создаётся только
через редактор — руками или через Editor-скрипты, которые нужно будет прогнать внутри
самого Unity, — поэтому она не входит в архив и её нужно собрать самостоятельно по
шагам ниже.

## 0. Что внутри архива

```
ColosseumDuel/

```

## 1. Распаковать и открыть в Unity

1. Распакуй архив в `C:\Users\avshu\Documents\Dev\ColosseumDuel` (или в любое другое
   место — папку `Dev` создавать не обязательно, это был просто предложенный путь).
2. `ProjectSettings/ProjectVersion.txt` сейчас указывает на `6000.0.36f1` — открой
   Unity Hub → вкладка **Installs** и посмотри свою точную версию Unity 6. Если она
   отличается — либо поправь `m_EditorVersion` в этом файле на свою, либо просто
   разреши Hub'у открыть проект другой версией редактора (он спросит и сконвертирует
   сам, это безопасно).
3. Unity Hub → **Open** → выбери папку `ColosseumDuel`. При первом открытии Unity
   сам сгенерирует папку `Library/` (это долго при первом разе, зависит от машины).
4. Если Unity Hub попросит поставить модуль **WebGL Build Support** — поставь через
   Hub → Installs → (три точки у своей версии) → Add modules.
5. Если Package Manager ругается на версии пакетов из `manifest.json` — открой
   **Window → Package Manager**, там можно принять предложенное автоматическое
   разрешение версий (Resolve), это нормально при небольшом расхождении версий пакетов.

## 2. Собрать сцену и UI (ручная работа в редакторе)

Логика готова, но её не с чем показывать — эту часть нужно сделать в самом Unity
(либо руками, либо написав собственные Editor-скрипты, которые создают объекты —
это можно попросить сделать отдельным шагом, когда дойдёт очередь):

- **Арена**: плоскость/цилиндр пола + стены (можно взять как референс визуал из
  веб-версии — процедурные текстуры песка/огня уже описаны в GDD).
  Добавь на пол коллайдер с именем/тегом, который использует `PlayerInputController`
  для рейкаста (см. TODO в файле).
- **Камера**: сверху вниз (top-down), как в оригинале.
- **Гладиаторы**: 2 GameObject'а (модели/примитивы), позиции которых каждый кадр
  синхронизируются из `GameController.Manager.State.P1.Active.Pos` /
  `...Bot.Active.Pos` (виртуальные координаты → мировые через `VirtualToWorld`).
  Раскраска шлемов: синий — игрок, красный — бот (как в веб-версии).
- **UI**: верхний бар (иконки состава/статус), нижний бар (карточки, кнопки
  "Защита"/"Способность"), баннеры фаз — подписаться на `GameController`'s
  `Manager.PhaseChanged` и обновлять UI по `MatchState.Phase`.
- **Ввод**: перетягивание для "рогатки" — заготовка в `PlayerInputController.cs`,
  доделать превью траектории через `GameManager.ComputeTrajectoryPreview(...)`
  (уже реализовано в Core, нужно просто нарисовать `LineRenderer` по точкам).
- **Эффекты**: вспышка/кольцо на активации способности, отталкивание при
  столкновении, огненное кольцо опасной зоны — визуальные детали, логика (когда
  это происходит) уже полностью в `Core`.

Ссылка на всё вышеперечисленное на уровне игровой логики (что чем управляется) —
см. `GameManager.cs`, там подробные комментарии по каждому шагу.

## 3. Git и GitHub

В папке проекта (после того как Unity хотя бы раз открыл его и сгенерировал `Library/`
— она не попадёт в репозиторий благодаря `.gitignore`):

```powershell
cd C:\Users\avshu\Documents\Dev\ColosseumDuel
git init
git add .
git commit -m "Initial Unity port of Colosseum Duel"
git branch -M main
git remote add origin https://github.com/<твой-юзернейм>/<репозиторий>.git
git push -u origin main
```

Если репозитория на GitHub ещё нет — создай его на github.com (New repository),
**не** добавляя README/gitignore при создании (они уже есть локально), иначе при
первом пуше будет конфликт.

## 4. GitHub Pages: вручную или через Actions

**Вариант A — вручную (проще для старта):**
1. File → Build Settings → WebGL → Switch Platform → Build (собери в отдельную
   папку, например `WebGLBuild/`).
2. **Player Settings → Publishing Settings → Compression Format → Disabled**
   (важно: GitHub Pages не отдаёт правильные заголовки для сжатых билдов Unity —
   без этого шага в браузере будет белый экран).
3. Содержимое `WebGLBuild/` (там `index.html`, `Build/`, `TemplateData/`) — в
   отдельную ветку `gh-pages` или в папку `/docs` на `main`, запушить.
4. GitHub → Settings → Pages → Source: выбрать эту ветку/папку.

**Вариант B — автоматически через уже добавленный workflow**
(`.github/workflows/unity-webgl-pages.yml`): при каждом пуше в `main` GitHub Actions
сам соберёт WebGL-билд и задеплоит на Pages. Для этого нужно один раз:
1. Получить лицензионный файл Unity для CI — через `game-ci/unity-request-activation-file`
   (инструкция: https://game.ci/docs/github/activation) — и добавить его как секрет
   репозитория `UNITY_LICENSE` (Settings → Secrets and variables → Actions).
2. Если используешь Unity Personal, дополнительно может понадобиться пройти
   активацию по email/паролю через секреты `UNITY_EMAIL`/`UNITY_PASSWORD` — детали
   в той же документации game.ci (там же описан weekly re-activation для Personal-лицензий).
3. GitHub → Settings → Pages → Source: **GitHub Actions** (не branch).
4. Запушить в `main` — билд соберётся и опубликуется автоматически; ссылка на
   игру появится в Settings → Pages после первого успешного деплоя.

## 5. Порядок, в котором лучше двигаться

1. Открыть проект в Unity, дождаться первой генерации `Library/`.
2. Собрать минимальную сцену (пол + 2 капсулы вместо гладиаторов + камера сверху) —
   и убедиться, что `GameController` тикает матч и гладиаторы двигаются по логике
   из `Core` (даже без финального визуала).
3. Добавить ввод (`PlayerInputController`) — проверить, что рогатка работает.
4. Добавить UI поверх.
5. Отполировать визуал (модели, огонь, кровь, эффекты — по референсу из GDD/скетчей).
6. Git init → push → включить Pages (вручную для быстрой проверки, потом можно
   перейти на автоматический Actions-деплой).
